# FLOW.md

How code travels between files and functions. Update the relevant flow whenever a call path changes. References are `path::name`.

## 1. App start (implemented)

`index.html` -> `src/main.tsx` creates the router (`routeTree` from `src/routeTree.gen.ts`, generated by the TanStack router plugin in `vite.config.ts`) with `queryClient` (`src/lib/query-client.ts`) in the router context and wraps it in `QueryClientProvider`. `src/routes/__root.tsx` adds `ThemeProvider` (`src/hooks/use-theme.tsx`, class `dark` on `<html>`, choice kept in localStorage), `TooltipProvider` and the toast `Toaster`.

## 2. Any API call (implemented)

Component -> feature hook (`useQuery`/`useMutation` in `src/features/<name>/api.ts`) -> `src/lib/api.ts::api.get/post/...` -> `apiRequest`: builds `/api/...` URL, sends cookies (`credentials: include`), adds `X-CSRFToken` from the `csrftoken` cookie on POST/PUT/PATCH/DELETE -> unwraps the backend envelope into `{data, meta, message}` or throws `ApiError` (`status`, `code`, `errors`). In dev, Vite proxies `/api` to the backend (`vite.config.ts::server.proxy`).

## 3. Current user (implemented client side; backend endpoint pending)

`src/features/auth/api.ts::currentUserQuery` -> `GET /api/me/`. 401/403 resolve to `null` (signed out). Sign in: browser navigates to `googleStartUrl()` (`/api/auth/google/start/?remember=&next=`); the backend completes Google OAuth, sets the session cookie and redirects back.

## 4. Tables (implemented)

Feature route -> query data (stable array) + module-scope columns -> `src/components/patterns/data-table.tsx::DataTable` -> TanStack Table v9 `useTable` with sorting; loading shows skeleton rows, empty shows the `empty` slot.

## 5. Page frame (implemented)

Route component -> `src/components/layout/app-shell.tsx::AppShell` (collapsible icon rail from `nav`, top bar with breadcrumb, actions and `ThemeToggle`) -> page content (`PageHeader`, `StatCard`, `DataTable`, ...).

## 6. Design preview (implemented)

`src/routes/design-preview.index.tsx` -> `src/features/design-preview/preview-page.tsx::DesignPreview` renders `sections/*` (foundations, actions, forms, data, navigation, menus, feedback, motion) with fake data from `data.ts`. `design-preview.frame.tsx` -> `frame-page.tsx` shows the AppShell with a tickets screen. `src/motion/icon-motion.ts::useIconMotion` wires `data-icon-motion` hover effects.

## 7. Public pages and sign-in (implemented, UI only)

`/` (`src/features/marketing/landing-page.tsx`), `/login` and `/signup` (`auth-page.tsx`) -> `google-button.tsx::GoogleButton` is an `<a>` to `src/features/auth/api.ts::googleStartUrl()` (full-page redirect to the backend's Google flow; the backend sets the session cookie and returns to `next`). `/terms` and `/privacy` -> `legal-page.tsx` with text from `legal-content.ts`. On failure the backend redirects to `/login?google_error=<code>`; `auth-page.tsx` shows the message from `GOOGLE_ERROR_MESSAGES`. The backend's post-login target defaults to `/app`, which does not exist yet. No route guard yet: signed-in users still see these pages.

## 8. Signed-in app (implemented)

- **Guard and shell:** `src/routes/app.tsx` -> `features/app/app-layout.tsx::AppLayout`: `currentUserQuery` (`GET /me/`) and `useWorkspaces` (`GET /workspaces/`, `features/workspaces/api.ts`) render `BootSkeleton` while loading (no route waits on the network); a null user navigates to `/login`; any 401 from any call goes to `/login` through `lib/query-client.ts` (query and mutation caches). `/app` (`app-home.tsx`) opens the last used workspace (localStorage, `getLastWorkspace`), else the first, else `/app/new`. Shell: `components/layout/app-shell.tsx` (router links, workspace switcher `features/app/workspace-switcher.tsx`, `ShortcutsMenu` with Win+K, ? and Ctrl+K, borderless `ThemeToggle`, account menu with Email and Account). "G then D/T/K/M" jumps come from `features/app/go-shortcuts.ts`.
- **Workspace routes:** `routes/app.$ws.tsx` -> `features/app/workspace-route.tsx::WorkspaceRoute` looks the id up in the cached workspace list (`useCurrentWorkspace`); an id that is not in it renders the 404 screen. Role comes from that list (`useWorkspace()` in `workspace-context.tsx`); ticket permissions come from `viewer.permissions` in the ticket overview. Owner-only actions are wrapped in `components/patterns/restricted.tsx::Restricted` (disabled button, reason in a tooltip).
- **Data rules (`lib/query-client.ts`):** no retries, no refetch on focus, reconnect or interval. A write updates cached data from its response or invalidates only the query on screen; other lists are marked stale with `refetchType: "none"`. Panels and tabs fetch only when open (members tabs, Files tab, categories, attach dialog). The only on-demand pull is `features/email/api.ts::useSyncMail` (`POST /email/gmail/sync/`).
- **Dashboard:** `routes/app.$ws.index.tsx` -> `features/dashboard/dashboard-page.tsx` -> `useDashboard` (`GET /workspaces/{id}/dashboard/?period=&tz=`, browser time zone) -> `StatCard`s, `components/patterns/volume-chart.tsx::VolumeChart`, three lists. Types follow `backend/docs/DASHBOARD_API.md`.
- **Tickets:** list `routes/app.$ws.tickets.index.tsx` -> `features/tickets/tickets-page.tsx` (URL search state validated in `search.ts`, `useTickets`, server-side ordering through `OrderContext`, `NewTicketDialog`). Detail `routes/app.$ws.tickets.$id.tsx` -> `ticket-page.tsx` -> `useTicketOverview` (one `GET .../overview/`); writes `useChangeStatus`, `useUpdateTicket`, `useAddMessage`, `useResendMessage` each refetch that one overview; "Load older" uses `useOlder` (paginated `messages/` and `events/`, on click only).
- **Filters (all tables):** page builds a `FilterDef[]` (select, date-range, boolean) from its URL search and passes `update`/clear callbacks -> `components/patterns/filter-bar.tsx::FilterBar` (search box, Filter menu, chips; values stay in the URL through `navigate({ search })`). **Assignment:** `ticket-page.tsx` Assignee row -> `useAssignTicket` (`POST tickets/{id}/assignee/`, then the overview refetches); tickets list `assignee` filter / My tickets tab -> `useTickets`. **Ticket menu:** three-dots -> `EditTicketDialog` or `history-dialog.tsx::HistoryDialog`.
- **Knowledge (one Articles page):** `knowledge-page.tsx` -> articles table (`useArticles`) + `files-section.tsx` (`useUploads`, same category/title filters); New -> `new-content-dialog.tsx` (category, then `/knowledge/new?category=` or `useUploadFile` with `category_id`); categories are managed from `settings-page.tsx` -> `category-controls.tsx::ManageCategoriesDialog`.
- **Knowledge graph:** graph view `?view=graph` -> lazy `knowledge-graph.tsx` -> `useArticleGraph` + `useCategories` -> `graph-layout.ts::buildKnowledgeGraph` -> React Flow. `knowledge-page.tsx` (Articles tab, or Files tab mounting `files-tab.tsx`), `article-page.tsx` (`NewArticlePage`, `ArticlePage`) with `article-editor.tsx` and `components/patterns/markdown.tsx` (react-markdown + rehype-sanitize). Upload: `useUploadFile` (content type from `uploadContentType(file.name)`) = `POST uploads/upload-url/`, direct `PUT` to the signed URL, `POST uploads/{id}/confirm/`.
- **Members and settings:** `members-page.tsx` (tabs mount `join-link-panel.tsx` and `invitations-panel.tsx` only when selected), `settings-page.tsx` (rename, portal toggle, logo via `useUploadLogo`, delete). **Audit:** `audit-page.tsx` (owner only; members get an explanation and no request). **Email:** `features/email/email-page.tsx` and `attach-dialog.tsx`. **Account:** `features/account/account-page.tsx`. **Join:** `routes/join.$token.tsx` (the click redeems, nothing is automatic). **Portal:** `routes/portal.$slug.tsx` -> `features/portal/portal-page.tsx` (public, honeypot field `website`, success shows the ticket number only).

## 9. AI settings and context search (implemented)

- **Settings:** `features/workspaces/settings-page.tsx` renders `features/ai/ai-settings.tsx` -> `useLlmSettings` (GET `/workspaces/{id}/llm/`) -> `useUpdateLlmSettings` (PATCH) / `useRemoveLlmKey` (DELETE `.../llm/key/`); each write returns the new settings, which replace the cached query.
- **Ticket context:** `features/tickets/ticket-page.tsx` owns `useTicketContext` (POST `.../tickets/{id}/context/`, optional `message_id`). The header button, the per-message button in `conversation.tsx` and `features/ai/context-panel.tsx` all use that one mutation; Each search marks the cached AI settings stale so the usage count refreshes on the next visit.
- **Ask page:** `routes/app.$ws.ask.tsx` -> `features/ai/ask-page.tsx`. History (three-dots menu -> `ask-history-dialog.tsx`): `useConversations` (GET `.../knowledge/ask/conversations/`), `useConversation` (GET `.../{id}/`), `useDeleteConversation` (DELETE). Asking: `useAskQuestion` (POST `.../knowledge/ask/` with the open chat's `conversation_id`) appends the returned turn to the cached chat, marks the list stale and refetches the AI usage shown above the box. `ask-messages.tsx` draws the bubbles and the thinking indicator; `splitCitations` turns `[n]` into links to the Sources list rendered by `ContextResults` (anchors `src-{turn}-{n}`).
- **Rendering:** `context-api.ts::splitHighlights` turns `⟦ ⟧` markers into parts; `context-panel.tsx` renders them as text and `<mark>`.
- **AI usage log (owner only):** AI settings (`ai-settings.tsx`, `isOwner` from `settings-page.tsx`) -> link to `/app/{ws}/ai-usage` -> `routes/app.$ws.ai-usage.tsx` (`validateUsageSearch`) -> `usage-page.tsx::UsagePage` -> `usage-api.ts::useAiUsage` (`GET /workspaces/{id}/ai/usage/`, offset pagination, `meta.summary`) -> `DataTable`; a row opens `Detail`. Filters and order are written to the URL by `update`.
